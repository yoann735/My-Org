3. ATTENTION — LE SQL EVIDENT EST FAUX
==============================================================================

Le SQL auquel on pense spontanement :

    update public.medrevise_records set deleted = false
     where store = 'questions' and record_id in (...);

NE FONCTIONNE PAS, et aggraverait la situation. Verifie sur la base :

    record_id        deleted   data
    qms5vsyu9ixfg    true      {}
    qmt8drm6darg8    true      {}
    qmt8drm6dayx7    true      {}
    ... (les 95, sans exception)

storage.js#remove() pousse ses tombstones avec data = {} : le CONTENU de la carte
n'est pas conserve cote cloud, seul l'identifiant l'est. Un simple deleted = false
ressusciterait donc 95 enregistrements VIDES, qui seraient ensuite adoptes par les
3 appareils (reconcileAll fait set(id, cloud.data), soit set(id, {})). On passerait
de 95 cartes absentes a 95 cartes fantomes, presentes mais sans recto, sans verso,
sans historique et sans dueDate — et sans moyen simple de les distinguer.

Le contenu ne peut venir que d'une seule source : ta sauvegarde de reference.
